# 25. EXECUTABLE GOVERNANCE LAYER

## Purpose

The executable governance layer translates PH6 doctrine from prose into

Authority: ZERO

---

## Canonical Files

| File                              | Role                                        |
| --------------------------------- | ------------------------------------------- |
| GOVERNANCE/governance_manifest.json     | Machine-readable registry of all governance files |
| GOVERNANCE/forbidden_terms_registry.json | Terms, fields, patterns forbidden in production |
| GOVERNANCE/schema_lock_registry.json    | Locked schemas, required fields, hash algorithm |
| TOOLS/ai_preflight_check.py       | AI session preflight validator              |
| TOOLS/governance_drift_scan.py    | Governance drift scanner                    |

---

## ai_preflight_check.py

Validates the governance layer is intact before any AI session that modifies
PH6 code.

Checks:

* All governance files present and parseable
* Canonical hash algorithm declared as BLAKE2b-256
* SHA256 not declared as canonical authority
* Lane-2 authority correctly set to ZERO
* Forbidden fields registry loaded and non-empty
* Schema lock registry loaded and non-empty

Exit 0 = PREFLIGHT PASS.
Exit 1 = PREFLIGHT FAIL — session must not proceed.

---

## governance_drift_scan.py

Scans a target tree for governance violations defined in the registries.

Checks:

| Check                    | Trigger                                              |
| ------------------------ | ---------------------------------------------------- |
| forbidden_terms          | Production code contains registry-listed terms       |
| sha256_authority_misuse  | hash_algorithm declared as sha256 (non-compat)       |
| lane2_pass_drop_leakage  | Lane-2 Python code issues PASS/DROP                  |
| blake2b_marker_regression| .blake2b marker absent where expected                |
| missing_governance_files | Manifest-declared files not found on disk            |
| forbidden_json_fields    | Evidence/schema JSON contains forbidden field names  |

Markdown prohibition-context filter:
Lines inside fenced code blocks or list items under headings containing
NEVER / FORBIDDEN / PROHIBITED / MUST NOT / RESTRICTIONS / Incorrect
are treated as definitional and are not flagged.

Exit 0 = PASS.
Exit 1 = FAIL_CRITICAL or FAIL_HIGH.

# 26. GOVERNANCE FAILURE CONDITIONS

## FAIL_CRITICAL Triggers

Any of the following causes an immediate FAIL_CRITICAL:

* A term from `forbidden_terms_registry.json` appears in non-definitional production code
* `hash_algorithm` declared as `sha256` outside a compatibility-only context
* A Lane-2 Python module issues `PASS` or `DROP` as an authority verdict
* A `.blake2b` commit marker is absent where the schema requires one
* A file declared in `governance_manifest.json` is missing from disk
* A JSON evidence or schema file contains a field name in `forbidden_fields`

---

## Mandatory Response to FAIL_CRITICAL

If the drift scanner exits nonzero:

STOP.

Do not proceed with the session.
Do not attempt autocorrection without human review.
Do not treat findings as advisory — they are blocking.

---

## FAIL_HIGH Triggers

* Governance manifest present but unparseable
* Forbidden terms registry loaded but empty
* Schema lock registry loaded but empty

FAIL_HIGH does not block by itself but must be acknowledged before proceeding.

---

## WARN Triggers

Drift indicators that are noted in the report but do not block the session.
Defined in `forbidden_terms_registry.json` under `severity: WARN`.
